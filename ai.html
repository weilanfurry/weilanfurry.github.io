Core Modules // 三个核心模块

只用三个概念，就能开始干活

Guessor 由 Nexabox 与牵引力工作室合作推出，在用户面前只有三个并列的入口，不暴露任何 Agent 技术概念。

01

模板 · 让它学会一件事

把你的规则、流程、格式和领域知识写成一份「工作说明书」交给它。 配置一次，之后在项目里、在临时任务里都能直接复用，不用每次重新交代。

能力复用 一次配置
02

应用空间 · 我的项目

一个长期存在的项目环境。目标、进度、文件、对话和记忆都在同一个空间里， 关掉软件再打开，看到的仍然是「这个项目现在是什么状态」。

长期项目 跨天继续
03

工作台 · 现在替我做

一次性的即时任务区。在你看得见的授权范围里，它可以直接整理文件、运行程序、 处理 PDF / 表格 / 文档，把一件具体的事做完。

真实执行 过程可见
Why Guessor // 为什么不一样

它解决的是四个断点

现有 AI 产品对普通消费者存在四类断点，Guessor 的产品设计围绕它们展开。

01

能力无法沉淀

每次对话都要重新交代角色、规则、格式与偏好。模板让能力一次配置、长期复用，结果更稳定。

PAIN // 重复劳动
02

会话无法延续

聊天窗口一关，上下文与产物就散了。应用空间让对话只是手段，项目本身成为主体。

PAIN // 无法长期做一件事
03

只能「说」不能「做」

输出停留在文字，用户还要自己搬运和执行。工作台让它在授权范围内真实操作电脑。

PAIN // 结果落地难
04

结果无法展示

做完的成果只能复制文本。一键生成可运行的动态应用或单文件报告，能演示、能交付。

PAIN // 无法交付
Value Chain // 用户价值链条

从「学会一件事」到「拿到一个成果」

所有界面、文案与流程都服务于这条链路，偏离链路的功能都会被削减。

学会一件事

用模板把可复用的能力交给 Agent。

建一个项目

用应用空间定义目标，交给它长期推进。

持续协作

对话、文件、进度与记忆都留在项目里。

拿到成果

生成可运行的应用，或可分享的报告。

Scenarios // 典型场景

普通用户真正会遇到的六件事

以下场景均为产品目标形态，随版本逐步开放。

#场景做什么拿到什么
S1用模板完成一项任务导入「PPT 制作」模板，描述需求本机的演示文稿文件
S2创建一个长期项目新建空间、选模板、交代目标结构化项目 + 对话记录
S3第二天继续推进回来提新要求，它先读项目状态再动手迭代后的项目
S4把项目变成应用点「生成动态应用」，预览并调试可运行的本地网页应用
S5把项目变成报告点「生成报告」，确认后导出单个 HTML 文件
S6处理一次电脑上的活说清任务、授权范围、看它执行整理好的本机文件 + 操作记录
Trust // 安全与可控

把电脑交给它之前，先让它变得可信

消费者敢不敢用，取决于它是否看得见、拦得住、退得回。

01

能看见的执行

正在做什么、结果如何、失败后怎么处理，都在界面上实时展开，不存在转圈的黑盒。

02

危险操作有人在场

默认「读自由、写确认、危险必问」。确认卡片用日常语言说明后果，拒绝后它会给出替代方案。

03

随时可撤销

每一轮改动都有快照，可以一键「撤销这些修改」；删除进回收站，保留 30 天。

04

本地优先

项目文件存放在你自己的电脑上，模板是纯文本，记忆以 Markdown 落盘，随时可查、可改、可备份。

Deliverables // 成果形态

一个项目，两种交付方式

生成能力属于项目本身，不是第四个模块。路线固定为两条，不做通用渲染框架。

A

动态应用

根据项目生成一个可以运行、可以点、可以交互的本地网页应用： 适合演示、数据查看、参数测算与轻量工具。生成后会先自检再交付， 打不开的结果不会交到用户手上。

能操作 可运行 本地预览
B

报告

把项目的完成度、关键成果、时间线与文件清单汇总成单个 HTML 文件： 样式内联、离线可用，双击就能打开，直接发给同事或客户。

能展示 单文件 可分享
● 一句话选择指南：要能操作，选动态应用；要能展示，选报告。
Beta 1 // 版本状态

先跑通一条完整链路

Beta 1 的目标不是功能多，而是验证「模板 → 应用空间 → 工作台 → 生成成果」这条链路是否真的有用。

方向Beta 1
模板新建 / 导入 / 编辑 / 启用停用 / 用于项目或临时任务
应用空间创建与打开、文件读写、项目状态、项目记忆、变更与撤销
工作台即时会话、文件操作、Python 执行、权限确认、操作记录
成果生成动态应用、生成报告、预览、导出
暂不提供账号与云同步、团队协作、插件体系、定时任务、模板市场
